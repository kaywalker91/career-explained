긴급전화 탭의 이름을 알게 됐어도, 화면 읽기 도구로 그 탭을 실행할 수 있어야 목록까지 이동할 수 있습니다. 또 목록이 열렸는데 선택 안내는 홈에 머물러 있다면 현재 위치를 이해하기 어렵습니다. 따라서 기능 이름·여는 동작·현재 선택을 같은 탭에 연결하는 것이 필요합니다.

후속 보관본(2026-01-10)의 공통 탭 함수는 Semantics로 이 정보를 전달합니다. 화면 읽기 도구가 요소의 뜻과 동작을 알아볼 수 있게 붙이는 설명입니다. 긴급전화 탭을 만들 때 기능 이름과 ‘두 번 탭하면 이동한다’는 조작 안내를 넣고, 실행 가능한 버튼이라는 역할도 지정합니다. 여기에 현재 선택 여부와 실행할 때의 처리까지 묶습니다. 코드에서는 이름을 label, 조작 안내를 hint, 선택 여부를 selected, 실행 처리를 onTap으로 지정합니다. 공통 탭 함수

탭 안에는 아이콘과 글자가 함께 있습니다. 이들이 각각 안내되는 대신 바깥에 붙인 설명을 사용하도록 excludeSemantics: true를 지정했습니다. 중복 안내를 조정할 수 있는 대신, 바깥 설명에 이름·상태·동작을 빠짐없이 담아야 합니다. 공통 함수로 네 탭을 만들면 같은 구성을 적용할 수 있습니다. 이 이점과 관리할 조건은 코드 구조를 해석한 것이며, 당시 본인이 비교한 대안이나 선택 발언을 새로 확정한 것은 아닙니다.

실행 뒤의 흐름을 긴급전화 탭으로 따라가 보겠습니다. 일반 터치를 받는 InkWell과 화면 읽기 도구의 실행 요청은 모두 같은 탭 선택 함수 _onItemTapped(index)로 이어집니다. 이 앱은 홈부터 네 탭을 0·1·2·3으로 구분하므로, 긴급전화 탭을 선택하면 현재 번호에 1을 저장합니다. 이어 앱 안의 웹 화면이 다른 내용 위에 열려 있다면 숨기도록 요청합니다.

화면을 구성하는 코드는 저장된 번호 1을 읽어 긴급전화 화면을 고릅니다. 각 탭도 같은 번호를 읽습니다. 긴급전화 탭은 자기 번호와 같으므로 선택된 상태를 전달하고, 홈 탭은 선택되지 않은 상태를 전달합니다. 화면을 고르는 기준과 현재 선택을 알리는 기준을 같은 값으로 연결한 구조입니다. 이 설명은 긴급전화 화면으로 이동하는 코드의 흐름이며 실제 전화 발신을 시험한 결과는 아닙니다. 탭 선택 처리 · 상태 구독과 화면 선택

화면 번역과 음성 접근성 안내는 다른 경로를 쓴다

앞에서 연결한 설명을 외국어 사용자가 이해할 수 있는지도 살펴봐야 합니다. 긴급전화 탭에 눈으로 보이는 문구는 선택한 언어의 문구 모음인 localizationData에서 가져옵니다. 하지만 화면 읽기 도구에 넘기는 이름은 SafeCall 버튼, 조작 안내는 “두 번 탭하면 SafeCall 화면으로 이동합니다.”라는 고정 문자열입니다. 다른 탭도 Home 버튼처럼 이름 일부와 조작 안내를 한국어로 고정해 두었습니다. 화면 문구와 고정 접근성 문구의 전달

앞의 공통 함수는 안쪽 글자의 의미 정보를 제외하고 바깥 설명을 사용합니다. 따라서 화면 글자가 선택한 언어로 바뀌어도 화면 읽기 도구에 주는 설명까지 같은 언어로 바뀐다고 볼 수 없습니다. 탭에 이름·선택·실행 정보를 붙인 구조는 확인했지만, 외국어 사용자를 위한 음성 안내 전체의 완성은 별도 확인 대상입니다.

앱이 재난 문자 본문을 읽어 주는 음성 기능과, TalkBack·VoiceOver가 버튼의 뜻을 읽는 기능도 서로 다른 경로입니다. 전자의 언어를 바꾸는 코드가 있다는 사실로 후자의 언어까지 맞는다고 판단하지 않습니다. 재난 문자 읽기의 언어 연결은 SEESUN-005의 별도 근거에서 다룹니다.

색상 조합을 관리하고 시험의 실제 기대값을 읽는다

화면을 보며 탭을 찾는 사람에게는 글자와 아이콘이 배경에서 잘 구별돼야 합니다. 보관 코드의 하단 탭 배경은 파란색 #1A3A6A입니다. 선택된 긴급전화 탭의 아이콘·글자는 흰색이고 글자는 굵게 표시합니다. 선택되지 않은 탭은 밝은 회색 #E0E0E0과 보통 굵기를 사용합니다. 앞에서 선택 안내를 만들 때 읽은 번호가 이 색상·굵기를 정할 때도 쓰입니다. 탭의 선택별 시각 표시

이 색들은 여러 화면이 함께 참조하는 공통 색상 파일에 모여 있습니다. 해당 값을 바꾸면 그 값을 쓰는 곳에 같은 색을 적용할 수 있습니다. 파일에는 밝은 글자색을 불투명하게 지정하고 일부 강조색을 더 진하게 정의한 내용도 있습니다. 다만 색 이름이나 한곳에 모았다는 사실만으로 읽기 쉬운지 판단할 수는 없습니다. 같은 글자색도 실제 배경·투명도에 따라 구별되는 정도가 달라지므로 사용하는 화면의 조합을 확인해야 합니다. 공통 색상 정의

코드에는 두 색의 밝기 차이를 비율로 계산하는 ContrastUtils와, 지정한 조합의 비율이 기대값 이상인지 검사하는 contrast_test.dart가 있습니다. 색을 바꾼 뒤 같은 조합을 다시 계산해 확인할 수 있도록 작성한 시험입니다. 다만 어떤 조합을 어느 기준으로 검사하는지까지 읽어야 시험의 범위를 알 수 있습니다. 대표적인 정의는 다음과 같습니다. 대비 계산 · 대표 조합의 시험 정의

시험에 지정한 조합 코드의 기대값
진한 기본 배경 primaryDark와 흰색·밝은 회색 글자 3:1 이상
흰 배경과 진한 글자 textDark 4.5:1 이상
흰 배경과 중간 글자 textMedium 3:1 이상

첫 행의 primaryDark는 하단 탭에 쓰는 primaryBlue와 다른 색입니다. 이 대표 시험을 하단 탭 자체의 검증 결과로 옮겨 쓸 수는 없습니다. 색상 파일의 주석에는 일반 글자의 기준을 4.5:1로 설명하지만, 위 시험 중에는 3:1 이상만 확인하도록 작성된 경우도 있습니다. 그 시험이 통과하더라도 해당 조합의 4.5:1 충족을 입증하는 것은 아닙니다.

따라서 주석의 “모든 조합 검증”이라는 표현보다 실제 시험 대상과 기대값을 먼저 읽습니다. 이번에는 Flutter 대비 시험을 실행하지 않았습니다. 표는 시험 정의를 대조한 결과이며, 실제 글자 크기·배경·투명도를 포함한 양 플랫폼 전체 화면의 검증은 남아 있습니다.

개선 완료 문서와 보관 코드를 함께 읽어야 한다

메뉴를 연 뒤 닫는 과정에서도 이름과 동작이 연결돼야 합니다. 메뉴 맨 위의 앱 소개와 닫기 버튼이 하나로 안내된다면, 사용자는 소개를 읽는 대상과 메뉴를 닫는 대상을 구별하기 어려울 수 있습니다. 헤더 개선 문서는 두 영역을 따로 나누고 닫기 버튼에 Close·Close navigation menu라는 설명을 붙였다고 기재합니다.

이를 고정 버전의 app_drawer.dart 215~274행과 대조했습니다. 앱 이름·소개 글, 누르기 처리를 갖춘 닫기 아이콘은 보이지만, 파일 전체에서 Semantics·Close navigation menu를 검색한 결과는 일치 0건입니다. 문서에 적힌 별도의 설명 구성을 이 보관 코드에서 확인하지 못한 차이가 있습니다. 검색 결과만으로 실제 화면 읽기 도구가 아무것도 읽지 않는다거나 닫기가 실패한다고 판단하지는 않습니다. 헤더 개선 문서 · 보관된 헤더 코드
